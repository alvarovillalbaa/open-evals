# Harbor product verification

Standing owner approval covers this exact free, disposable scope. One public
Ubuntu 24.04 job, capped at 20 minutes, checks the pinned source commit; an
activation-only child adds the temporary workflow. Never merge that workflow.

- 18 new core protocol cases, HB-E01–18: immutable source/version/plan bindings,
  derived deadlines, one claim, identical replay, incompatible completion,
  unknown/recovery and operational failures. The 16 transport cases also run
  against the expanded shared module loader; those are regressions, not new IDs.
- 23 API/SDK/CLI cases, HB-A01–23, use a newly created loopback PostgreSQL
  database with an exact ownership comment. They cover authentication, workspace
  and project boundaries, preview/no-write, SQL CAS, immutable/idempotent saves,
  generic-reader/writer fencing, atomic audit rollback, once-only claims,
  redacted report readback, explicit recovery and no automatic dispatch retry.
  HB-A22 executes the actual Node CLI, installed Python component and Harbor
  oracle once, then compares the original native result to the saved report.
- Four Chromium cases, HB-B01–04: desktop authored import/versioning; narrow
  exact-source plan sharing/save/reload; desktop actual CLI result readback and
  interruption closure; narrow failure/draft preservation and viewer access.
  No retries; all browser requests are confined to the disposable loopback app.
- The normal workspace build runs. Frozen dependencies are installed only in
  an owned copy of tracked source, excluding historical node_modules entries.
  Original tracked bytes are sealed before/after; copied runtime source is
  compared after the checks, with next-env.d.ts generated only in that copy.
